Baseline

The calendar page as it is today

This is a faithful reproduction of the shipped UI — toolbar, month grid, chips, task chips and toolbar controls all copied class-for-class from the real components. Use it to compare against the three prototypes. Every number here is a real measurement from the code, not a guess.

Where the styling splits from the marketing pages

  • The app shell is slate + #dd5822. The marketing pages are warm cream #F8F6F3 with blush #FED5CF, powder blue #BEDAE3, mint #C4E9DA, peach #F1B598 and lavender #D3C7E6. The calendar uses none of that palette.
  • Marketing surfaces are rounded-2xl / rounded-3xl with coloured shadows (shadow-lg shadow-[#c45e38]/30), rounded-full buttons, gradient cards, blurred orbs and glass. The calendar is flat white boxes with shadow-sm and rounded-lg chips.
  • Marketing has one primary action per surface. The toolbar has six bordered control clusters in one row (nav / view / Add / Select / 4 icon links), each with its own border and background — no hierarchy to read.

Hard numbers worth quoting

11px event chipstext-[11px] with py-[3px] and min-h-[26px] tap targets. Apple's floor is 44px; Material's is 48px.
72 / 104px cellsmin-h-[72px] → sm:min-h-[104px]. At 104px a cell fits 3 event chips + 2 task chips + overflow, so anything more is hidden behind “+N more”.
1440px of week grid24h × 60px in a max-h-[60vh] scroller. No scroll-to-now, no working-hours focus. 3am occupies as much room as 5pm.
0 filtersNo calendar toggle, no member filter, no search, no legend. Event colour is discoverable only by hovering a chip. CalendarSelector.svelte (92 lines) exists but has no importers.
Day view is a secretFour views exist; the toggle offers three. Day is reachable only by tapping a date cell.
Full-bleed, no containerMonthView is a bare grid-cols-7 with no max-width. On a 27” display the grid stretches edge to edge with 11px chips. Marketing caps at max-w-7xl px-6.
Ad events inside the scheduleborder-amber-300 bg-amber-100 chips sit in the same grid as family events, breaking the palette with a colour that means “warning” in the rest of the app.
Tasks read as broken UIDashed grey border on bg-slate-50 — the standard “disabled” affordance. Tasks are a first-class concept in the domain (CONTEXT.md) but look second-class on the grid.

What already works and must not be lost

Prototypes A, B and C all keep the whole feature set. If you adopt any of them, this is the contract:

  • Drag-move between days with 15-minute snap (eventMove.ts)
  • Range-select → floating pill with −15 / +15 / Create / ✕ (rangeSelect.ts)
  • Add mode for touch range-select, mutually exclusive with Select mode
  • Bulk edit bar: move-to-calendar, location, attendants, smart 2-phase dry-run plan
  • NLP quick add with multi-parse “create all” and mis-parse reporting
  • Event ⇄ Task tabs, recurrence, RSVP, checklists, attendants, offline queue
  • Delete scopes: this occurrence / whole series / single
  • Recurring-task cursor sync, overdue highlighting, RSVP tint, creator + attendance badges
  • Swipe month nav, deep links (?date=, ?view=, ?edit=, ?quickadd=), PWA share target
  • Print view, .ics export, Google Calendar link, import
