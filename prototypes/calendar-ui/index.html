One root cause, eight symptoms

The marketing pages were designed as warm, spacious, soft-edged. The calendar was built as a dense, cold, bordered admin grid. Two design languages, one product.

2unrelated design languages. Marketing = cream #F8F6F3 + 5 pastels. App = slate + #dd5822. The calendar uses zero of the marketing palette.
11pxevent chips with 26px tap targets (text-[11px], min-h-[26px]). The marketing pages never go below 12px.
0filters. No calendar toggle, no member filter, no search, no legend. CalendarSelector.svelte exists — 92 lines, zero importers.
6bordered control clusters in one toolbar row (nav · views · Add · Select · 4 icon links). No visual hierarchy.

Recommendation

Ship A now, then B, and treat C as a bet.

A closes the whole style gap for a class-level change in six files and no state machine touched. It also fixes the two real usability bugs (11px tap targets, Day view being unreachable). B is where the genuine functional win is — zero filters on a shared family calendar is the largest gap, not the colours. C is the only one that risks the power-user habit of scanning the month, so it should be behind a toggle and measured.

Order of work
  1. Tokens first. Add a calendars.css with the marketing palette as CSS vars. Zero behaviour change, lets every later step be reviewed as pure restyle.
  2. Accessibility floor. 11px → 12px chips, 26px → 28px+ targets, 44px on the primary +. Independent of style direction — do it either way.
  3. Prototype A as-is: cream canvas, glass frame, brand chips, Day view in the toggle.
  4. Filters — a CalendarFilters.svelte plus a hiddenCalendarIds store. Also delete the orphaned CalendarSelector.svelte or wire it.
  5. Prototype B rail on desktop, drawer on mobile.
  6. Prototype C behind localStorage, measure scroll-depth before deciding.
Do not break
  • Print view — /calendar/print inherits these classes. Gate every decorative change behind print: variants, the way the app already does.
  • 41 colocated tests assert class strings. Restyling is a test-breaking change by definition — update the assertions deliberately, don't loosen them.
  • Contrast. Chips become tinted backgrounds, so the text-slate-800-on-tint pairing has to clear 4.5:1 at 12px. #FED5CF with slate-800 does; the lighter tints need checking.
  • Mobile keeps today's 3-chip + action-sheet behaviour. Only the skin changes below 640px.
