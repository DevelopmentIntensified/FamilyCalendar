## Agent Brief

**Category:** bug
**Summary:** The web tasks page shows neither a start-focus affordance nor accumulated focus time on a task row, though the phone's TaskFocus lane already drives the same `/api/taskfocus/commands` channel (#212, #293).

**Current behavior:** `src/routes/(calendar)/calendar/tasks/+page.svelte` + `src/lib/components/tasks/TaskRow*.svelte` render priority/assignee/due chips only. `TaskDto` already carries `focusMinutes`/`focusStartedAt`, the server has `/api/taskfocus/commands` (device channel the phone enqueues start/stop on), and `apps/android` shows/start focus from the SAME commands. The desktop has no row affordance and no "logged" chip.

**Desired behavior:**
- A row affordance to START focus on the task for the current user; a second tap STOPS it (mirrors the phone's one-wrapper-per-task semantics).
- The row shows accumulated `focusMinutes` (e.g. a small `25m` focus chip next to due/assignee) while the task carries any.
- While a session is live the row shows the active state (the phone mirrors it via `phone:enqueued` on the same channel — verify the mirror triggers on desktop-initiated commands too).

**Key interfaces:** `TaskDto.focusMinutes`, `focusStartedAt`; `/api/taskfocus/commands` POST `{command: start|stop, taskId}`; device channel already wired for the phone side (`PushGraph.session`, `EventsChangedRun`). Reuse the web client's existing API wrapper — no new endpoints.

**Acceptance criteria:**
- [ ] Aタ task row without focus shows a "Start focus" affordance; tapping it starts a session and the row flips to active.
- [ ] A second tap stops it; `focusMinutes` reflects the run after the server confirms.
- [ ] Rows that carry minutes show the chip; rows without don't.
- [ ] A Playwright-backed or unit test pins the affordance + chip per state.

**Out of scope:** phone changes (already shipped), dashboard focus widgets.
