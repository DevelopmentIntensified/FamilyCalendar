## Agent Brief

**Category:** enhancement
**Summary:** Add a "create event" action to text selection (system-wide and in-app) that turns selected dates/details into a prefilled event form: on-device extraction first, server parse as fallback.

**Current behavior:**
- No selection-menu integration exists anywhere: no system text-processing registration, no in-app selection actions. The only parse path is typing into the form's Quick Add. The web has a floating create-from-selection bar as the reference behavior.

**Desired behavior:**
- Selecting text anywhere on the device offers a FamilyPlanz action that opens the event form prefilled from the selection.
- Selecting text in the event detail sheet / form offers the same in-app.
- Parsing tries on-device entity extraction first (dates/times/places) and falls back to the existing server parse endpoint — including always-server on builds without Play services.
- Prefill behaves like Quick Add (fields marked as parsed, user confirms — a parse is a hint, never a commit).

**Key interfaces:**
- The platform text-processing intent for the system-wide entry.
- The in-app selection container / detail-sheet text for the in-app entry.
- The existing server parse endpoint (fallback path).
- The on-device entity-extraction API (primary path; must degrade cleanly when unavailable).

**Acceptance criteria:**
- [ ] Selecting "Dinner Friday 7pm" in another app offers FamilyPlanz and opens a prefilled form.
- [ ] On a Play-services-less build the same flow works via the server fallback.
- [ ] In-app selection in the detail sheet offers the same action.
- [ ] Prefilled fields carry the parsed marks; nothing saves without confirmation.
- [ ] Tests pin fallback routing (on-device present vs absent).

**Out of scope:**
- New NLP beyond the existing parse endpoint's capabilities.
- Task creation from selection (event only; extend later).
