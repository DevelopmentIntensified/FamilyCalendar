# 304 — Android system back closes the app; add back/forward navigation

Status: in-progress
Roles: bug · ready-for-agent

> *This was generated by AI during triage.*

Owner decision (grill 2026-11-10): back pops route history; forward is an in-app button shown when a forward stack exists.

## Agent Brief

**Category:** bug
**Summary:** System back must walk back through navigation history instead of exiting, and a forward affordance must redo it.

**Current behavior:**
- The navigator holds a single replaceable route with no history; nothing registers a back callback. System back falls through and finishes the activity. Confirmed on-device (0.3.0): Calendar → Dashboard → back exits to the launcher.

**Desired behavior:**
- Every route change pushes history; system back pops to the previous route.
- Popping populates a forward stack; an in-app forward button appears (navbar) only while the forward stack is non-empty and advances through it.
- Back on the start route exits the app (standard platform behavior).
- Deep links, push opens, and reminder taps push onto history like normal navigation.
- History survives rotation; process-death restore keeps at least the current route.

**Key interfaces:**
- The app navigator (single-route state today): add back + forward stacks.
- The host activity: register a back callback that pops instead of finishing.
- The navbar: conditional forward affordance.

**Acceptance criteria:**
- [ ] Calendar → Dashboard → back lands on Calendar (app stays open).
- [ ] After back, the forward button appears and returns to Dashboard.
- [ ] Forward button is absent with an empty forward stack.
- [ ] Back on the start route exits the app.
- [ ] Tests pin push/pop/forward/exit transitions.

**Out of scope:**
- Tab sub-state (e.g. family sub-routes): route-level history only.
- Predictive-back animations.
