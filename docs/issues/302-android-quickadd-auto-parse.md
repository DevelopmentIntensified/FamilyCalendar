## Agent Brief

**Category:** bug + enhancement
**Summary:** Bring Android quick-add parsing to web parity: automatic, multi-result, with working phrase reporting and cloud-AI opt-out honored.

**Current behavior:**
- Parsing requires tapping a manual "Parse" affordance; nothing happens while typing.
- When several events are detected, only the first is used — the web's "N events detected / create N events" panel doesn't exist.
- The "parsed wrong? report this phrase" affordance has no handler — a dead tap.
- Parse requests never send the cloud-AI flag, so the user's cloud-AI opt-out is ignored (server defaults to cloud on).

**Desired behavior:**
- Typing in Quick Add auto-parses on a short debounce, unless the user disabled the auto-parse setting (default on).
- Multi-event results show a panel offering to create each detected event.
- Reporting a phrase submits it to the phrase-report endpoint with an ack.
- The cloud-AI flag from user settings is sent with every parse request.

**Key interfaces:**
- The Quick Add block in the event form: add debounced auto-trigger honoring the auto-parse setting.
- The calendar ViewModel's parse handler: keep multi-result responses, not just the first.
- The existing parse request DTO: add the cloud flag field.
- The phrase-report endpoint the web already uses for mis-parses.

**Acceptance criteria:**
- [ ] Typing a phrase auto-fills the form within ~1s without tapping Parse.
- [ ] Disabling the auto-parse setting restores manual-only behavior.
- [ ] A two-event phrase offers both events for creation.
- [ ] Reporting a phrase hits the report endpoint and acks.
- [ ] Parse requests carry the user's cloud-AI setting.
- [ ] Compose/ViewModel tests pin auto-trigger, multi-result, report, and flag.

**Out of scope:**
- The create/edit payload contract — that's #301.
- Control visuals — that's #309.
