# 124 — The phone tracks focus sessions too, and they sync

Status: in-progress
Roles: enhancement · owner-decided

Owner, 2026-11-03: *"The mobile app should also have the focus session tracking, not just
desktop side, and it should sync."*

Until now the desktop was the only clock (079): the phone could only *ask* the desktop to
start or stop. Now the FamilyPlanz Android app times focus itself, without enforcement. It's
for focus away from the computer, and that time must reach everything else: the server, the
web, the desktop's reports and totals.

## Design: one writer per field still holds

The phone does not write `focusMinutes`. It writes its own **session log** on FamilyPlanz.
The desktop **absorbs** finished phone sessions into its local history, then pushes the
new total as usual, then acks them. Until a session is absorbed, the server reports it
separately so the phone and web show the right total immediately, even with the desktop off.

```
phone ──POST/PATCH──▶ taskfocus_sessions (server) ──GET unabsorbed──▶ desktop
                         │                                             │ import as local
                         │◀──────────── POST …/absorb ─────────────────┤ session + span,
                         │                                             │ PUT focusMinutes first
GET /api/tasks: focusMinutes (desktop) + phoneFocusMinutes (unabsorbed closed)
                + phoneFocusStartedAt (open phone session)
```

No double count:
- Before absorption, phone time is only in `phoneFocusMinutes`.
- After absorption, it's only in `focusMinutes`. The desktop PUTs the new `focusMinutes` *before* acking; between those two steps a reader can briefly see it twice. That's bounded to one request and corrects on the next read.
- If phone and desktop time the same task over the same wall-clock period, the desktop's per-task interval union (`SessionRepo.Report`) counts the overlap once.

## Server contract (FamilyPlanz)

Table `taskfocus_sessions`:
- `id` text pk, `user_id` FK cascade, `task_id` FK cascade;
- `started_at` timestamptz not null, `ended_at` timestamptz null (null = running);
- `source` text not null default `'phone'`;
- `absorbed_at` timestamptz null;
- `created_at`;
- index on (`user_id`, `absorbed_at`, `started_at`).

All endpoints take the same Bearer/session auth as `/api/tasks` and are user-scoped. The task
must be the caller's (owned or assigned).

| Call | Body | Result |
|---|---|---|
| `POST /api/taskfocus/sessions` | `{taskId, startedAt, endedAt?}` | 201 `{session}`. `endedAt` present = a finished session recorded offline. Rejects `endedAt <= startedAt`, starts > 5 min in the future, and durations > 12 h (400). |
| `PATCH /api/taskfocus/sessions/{id}` | `{endedAt}` | 200 `{session}`. Closes an open session. 404 if not yours; 409 if already absorbed. |
| `DELETE /api/taskfocus/sessions/{id}` | — | 200. Discards an unabsorbed session (the user cancelled). 404 is treated as done. |
| `GET /api/taskfocus/sessions?unabsorbed=1` | — | 200 `{sessions:[{id,taskId,startedAt,endedAt,source}]}`. Closed and unabsorbed only, oldest first, limit 200. |
| `POST /api/taskfocus/sessions/{id}/absorb` | — | 200, idempotent: already absorbed returns 200, unknown returns 404 (treated as done). Only closed sessions can be absorbed. |

`GET /api/tasks` also returns, per task:
- `phoneFocusMinutes` (int ≥ 0): whole minutes of the caller's *closed, unabsorbed* phone
  sessions;
- `phoneFocusStartedAt` (ISO | null): the start of an *open* phone session on that task.

The existing `focusMinutes` and `focusStartedAt` are unchanged and remain desktop-owned.

## Display rule (phone, web)

```
live = focusMinutes + phoneFocusMinutes
     + (focusStartedAt      ? now − focusStartedAt      : 0)
     + (phoneFocusStartedAt ? now − phoneFocusStartedAt : 0)
```

The desktop and the phone running at the same moment is the one case this overcounts on
the phone, until the desktop absorbs the session; the desktop's own totals are exact.
Running = either start field set. The chip says where: "Focusing (desktop)" or "Focusing
(phone)".

## Phone (FamilyPlanz Android)

- A "Focus here" action starts a phone session: POST with `startedAt` = now. The open session id is
  kept locally so the timer survives app restarts. "Stop" PATCHes `endedAt`.
- One phone session at a time; starting another closes the previous one first.
- Offline: start and stop are recorded locally and uploaded later as one finished POST.
  Nothing is lost if the app dies, because the local record carries the start time.
- The ask-the-desktop action (079 commands) stays, as a secondary "Focus on desktop".
- No enforcement on the phone, ever.

## Desktop (TaskFocus) — this repo

- Each sync (full, linked, periodic), **after** the pull and category reconcile and **before** the focus
  pass:
  - `GET …/sessions?unabsorbed=1`.
  - For each session whose `taskId` maps to a linked local task: import it as a local session plus a
    focus span. Mark it `source = phone` and record the remote id in a new
    `phone_sessions(remote_id PK, session_id)` table, so a re-import is a no-op.
  - If the task is unknown locally, leave the session unabsorbed and log it.
- The focus pass then PUTs `focusMinutes`, which now includes the imported time (closed spans).
- **Only after** that PUT succeeded for a task, `POST …/absorb` that task's sessions. If a PUT
  fails, its sessions stay unabsorbed and are retried next run; the import is idempotent.
- A 404 on the list endpoint (server predates 124) means skip, quietly.
- Reports and the session log show imported sessions like any other, marked "phone".
