## Agent Brief

**Category:** bug
**Summary:** Android event create/edit requests don't match the server contract, so fields are silently lost and one input shape dead-ends with no feedback.

**Current behavior:**
- Create posts only title/start/end/allDay/location/description. The repeat picker, reminder picker, and calendar picker the form collects are never serialized — the saved event silently lacks them.
- Edit sends `date`/`startTime`/`endTime` keys the server ignores (it reads `start`/`end`/`allDay`/etc.), plus a `scope` value the server doesn't recognize — so time edits "succeed" with no change and occurrence edits hit the wrong target.
- A malformed date keeps the Create button enabled but produces no request, no toast, no hint — a dead tap.

**Desired behavior:**
- Create and edit payloads carry every field the form collects (reminder, recurrence, calendar, all-day, dates, times), mirroring the web form's submit preparation.
- Occurrence-scope edits use the server's occurrence scope value.
- An unparseable date disables Create and shows a hint, like the existing end-before-start hint.

**Key interfaces:**
- The event create-request DTO: extend with the missing optional fields the server already accepts.
- The form's update-body builder: emit the server's field names (`start`, not `date`+`startTime`).
- The form's `valid` predicate: reject unparseable dates.
- The server contract: POST accepts reminder/recurrence/calendar; PUT reads partal bodies with `start`/`end`/`title`/`allDay`/`reminderMinutes`/recurrence keys and scope `this` for one occurrence.

**Acceptance criteria:**
- [ ] Creating an event with repeat + reminder + non-default calendar persists all three server-side.
- [ ] Editing an event's start/end time persists the change.
- [ ] Editing one occurrence of a repeating event targets that occurrence.
- [ ] A garbage date string disables Create and shows a hint (no dead tap).
- [ ] Robolectric/ViewModel tests pin each fixed payload shape.

**Out of scope:**
- Control visuals (dropdowns/pickers/search) — that's #309.
- Quick-add parsing — that's #302.
