# admin

**screen** — Admin shell: tab layout and badge counts, the `/admin` index, and the two register pages' bodies over feedback's components.

Domain words come from [CONTEXT.md](../../../../CONTEXT.md); use them exactly. Architecture rules: [docs/architecture/rules.md](../../../../docs/architecture/rules.md).

## Purpose

- Owns: the admin area's frame — header, the two section tabs with their open-count badges, "← Back to app", the one toast list, and the Toaster; the `/admin` index page's heading and two section cards.
- Owns: the two register pages' bodies (`/admin/bugs`, `/admin/nlp`) — heading, subtitle, "Export for agent" and the composition of feedback's register — and their page data: feedback's rows plus the clock and zone the export text is rendered with.
- Owns: the one badge-count read that both the `(admin)` layout data and `/api/admin` answer with, including the per-leg rule that a failing count reads 0 instead of failing the page or the JSON call.
- Does not own: the bug-report and unmatched-phrase registers (rows, resolve service, export text rules, register/export components) — those belong to `feedback`. This screen never touches their tables; it asks `feedback` for the rows and the counts.
- Does not own: the `/admin` page gate. The app's session pipeline (hooks) redirects `/admin` document requests; this screen only makes the reachable `/api/admin` check explicit through `endpoint` auth `admin`. The global `admin` role rule itself is kernel's `actor.isAdmin`, built once from the user row.

## Public interface

Designed in S1, before the code, and finished in S7/S8. `AdminCounts`, `ADMIN_SECTIONS`, `getAdminCounts` and the two components each have two or more callers, so deleting one would paste its body unchanged into each (the deletion test). The handlers are the builder definitions their route files re-export (conventions: no logic in routes).

- `index.ts`:
  - `AdminCounts` — `{ openBugs: number; openPhrases: number }` (from `admin.contract.ts`). The layout model, the shell badges and the `/api/admin` body share this one shape, so the nav and the JSON cannot disagree.
  - `AdminBugRegisterData` / `AdminPhraseRegisterData` — one register page's load data: feedback's `{ open, resolved }` rows plus `now: Date` and `zone: string`. The zone is feedback's export zone (`'UTC'`), so the page's text and `GET /api/admin/*`'s are byte-identical.
  - `ADMIN_SECTIONS` — the closed, ordered list of admin sections: href, label, the index card's icon and blurb, which count key feeds its badge, and the badge colours. Bug Reports (red, `openBugs`) first, Unmatched Phrases (slate, `openPhrases`) second. One home for the destinations and copy the legacy layout and index page each hard-coded.
  - `isAdminSectionActive(pathname, href)` — the shell's active rule: a tab is active on its exact path or any child path; a sibling that merely shares the prefix (`/admin/nlpx`) is not.
- `index.server.ts`:
  - `getAdminCounts(ctx)` → `AdminCounts` — calls `feedback`'s per-register open counts (`openBugReportCount`, `openUnmatchedPhraseCount`), one leg after the other because `ctx.db` may be one transaction session; each leg independently degrades to 0 and logs `admin_count_failed`. The single composition behind both the layout data and `/api/admin`.
  - `adminCountsEndpoint` — `GET /api/admin`: `endpoint` with auth `admin`, no input, body `AdminCounts`.
  - `adminLayoutLoad` — the `(admin)` group layout `load`: `pageLoad` with auth `admin`, returning `AdminCounts` as the layout data the shell consumes.
  - `adminBugRegisterPageLoad` / `adminPhraseRegisterPageLoad` — the register pages' `load`: `pageLoad` auth `admin`, feedback's `listFeedback` for the kind plus `ctx.clock.now()` and `'UTC'`.
  - `adminResolveBugReportAction` / `adminResolveUnmatchedPhraseAction` — the register pages' `?/resolve`: `formAction` auth `admin`; resolves a non-empty `id` through feedback's `resolveFeedback` and answers the legacy `{ success: true }` even for an id that no row carries.
- `ui/index.ts`:
  - `AdminShell` — the admin frame: header with `🛠 Admin` (aria-label "Admin home"), the section nav (aria-label "Admin sections") with active state and count badges, "← Back to app" → `/calendar`, a children snippet, and the Toaster. No app Navbar, BottomNav or breadcrumbs; `pathname` is a prop.
  - `AdminHome` — the `/admin` index: heading "Admin", subtitle "Triage user feedback and parser gaps.", and the two section cards with `N open` badges.
  - `AdminBugRegister` / `AdminPhraseRegister` — the two register page bodies: heading, subtitle, export panel and feedback's register; props `data` (the page data), `api` (feedback's browser client) and `toasts` (the screen's `adminToasts`).
  - `adminToasts` — the area's toast list, from `admin.toasts.state.svelte.ts`: the shell renders it, the pages report into it.

## How to test

- Whole module: `npm run test:mod -- admin`.
- Pure rules: `admin.sections.rules.test.ts`, plain tables of input → expected output, no setup.
- Database + services: `admin.service.db.test.ts` using `rollbackTest` and `testCtx({ db })` (needs Postgres: `docker start familycalendar-db`).
- HTTP contract: `admin.http.db.test.ts` pins status + body of `GET /api/admin` (golden tests, committed mode) and stays unchanged after the port.
- Page wiring: `admin.pages.http.db.test.ts` calls the layout load and both register loads/actions through `invokeLoad` / `invokeAction`: counts and rows for an admin, the two redirects, the two refusals, the resolve and its legacy success answers.
- Endpoint gate: `admin.counts.http.db.test.ts` calls `adminCountsEndpoint.handler` through `invoke`: 401 / 403 / the counts, independent of the golden.
- UI: `ui/*.svelte.test.ts` render with props (`pathname`, counts, page data, a fake transport behind the real api client, `memoryToasts()`); the shell's active-section rule is also tested without a DOM in `admin.sections.rules.test.ts`.
- Fixtures: none — the screen owns no rows, so db tests seed `feedback`'s `bugReports` / `unmatchedPhrases` rows directly.

## Depends on

- May import: kernel + every domain (public entries only); never another screen.
- Owns tables: none.
- Reads (join only): none.
