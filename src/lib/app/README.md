# app

**app**, the composition root. This is the only place where real adapters are chosen and all the modules are wired together. Nothing else in `src/lib` imports `app`.

Domain words come from [CONTEXT.md](../../../CONTEXT.md). Architecture rules: [docs/architecture/rules.md](../../../docs/architecture/rules.md).

## Purpose

- **Owns:**
  - the production `Ctx` (`appCtx`);
  - while the rewrite is in progress, the bridges from that Ctx to legacy singletons;
  - the request pipeline `src/hooks.server.ts` wires (`requestPipeline.server.ts`: hook order, Bearer and cookie sessions, the Anonymous Account fallback, the admin gate, `handleError`);
  - the retention run behind the cleanup cron (`runRetention`) and the two infrastructure endpoints, `/api/cron/cleanup` and `/api/health` (APP-01);
- **Does not own:** business rules. If app code starts deciding things, move that logic into a domain.

## Public interface

- `appCtx`: put on `event.locals.ctx` by the request pipeline ([requestPipeline.server.ts](requestPipeline.server.ts)) before any other hook runs. Route files and module code never import it. They receive it through `locals.ctx` and the HTTP builders.
- `appHandle` / `appHandleError` / `createAppHandle` / `createAppHandleError`: the two hooks `src/hooks.server.ts` exports, and the same hooks over an injected ctx (what the pipeline's test builds).
- `cleanupCronEndpoint` / `healthEndpoint` ([appRoutes.server.ts](appRoutes.server.ts)): the `+server.ts` files re-export them as `GET`/`POST`.
- `runRetention(ctx)` ([retention.server.ts](retention.server.ts)): the cleanup body; only the cron endpoint calls it.

## How to test

- `npx vitest run --project db src/lib/app` — every app db test: the pipeline (headers and origin check, Bearer and cookie sessions, the Anonymous Account fallback, the admin gate, `handleError` filing), `runRetention`'s windows, and the two routes' wire. They import `$lib/kernel/db/tables.server`, so they run in the db project (R3).
- `npx vitest run --project unit src/lib/app/pushTransport.test.ts` — the push bridge and its mapping.

## Invariants

- `locals.ctx` and `locals.actor` are set on every request, before route code runs. `locals.actor` always mirrors `locals.user`: a bearer token gives `via: 'token'`, a cookie or anonymous account gives `via: 'session'`. `app.requestPipeline.db.test.ts › Bearer tokens`, `› cookie path`, `› Anonymous Account fallback`.
- Hook order stays: security headers, then API origin check, then session. Hooks are composed by hand, not with `sequence()`, so they can be invoked directly in tests (see the comment in [requestPipeline.server.ts](requestPipeline.server.ts)). `app.requestPipeline.db.test.ts › hook order and the API origin check`.
- Every decision in the pipeline is a module rule or service, never app code: identity's `resolveBearer` (asked only on `/api/*`), `resolveSessionCookie` (validate, roll the cookie, blank-cookie cascade, hourly `lastActiveAt` touch) and `shouldCreateAnonymousAccount` (a `GET` + `text/html` document navigation on a protected route); access's `isAdminRoute`/`isProtectedRoute` (segment match, so `/disclaimer` is not `/claim`). The admin gate runs before the Anonymous Account fallback. `app.requestPipeline.db.test.ts`, `identity.person.rules.test.ts`, `access.route.rules.test.ts`.
- `process.env` is read here and nowhere else in `src/lib` (R6): `CRON_SECRET` for cron endpoints, `RESEND_API_KEY` and `NOREPLYEMAIL` for `ctx.mail`, `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY`/`VAPID_SUBJECT` and `FCM_SERVICE_ACCOUNT_JSON` for `ctx.push`, `CEREBRAS_API_KEY`/`CEREBRAS_MODEL`/`CEREBRAS_API_URL` for `ctx.ai`, `BETTER_AUTH_SECRET`, `EMAILSECRET` and `NODE_ENV` for the session cookie's signing secret, the email-code pepper and the production flag, and `DATABASE_DISABLE_MIGRATIONS` for the cold-start migration kick-off in [requestPipeline.server.ts](requestPipeline.server.ts). The kernel adapters receive those values as parameters, so a kernel or module test never touches the environment.
- The fault path is fail-safe: `ctx.faults.report` calls `feedback`'s `fileAutoBugReport`, which never throws (it skips anonymous callers, throttles itself and catches/logs a failed insert), so a failed auto-report can never change the response. The pipeline's `handleError` calls the same service directly, awaits it inside legacy's own try/catch fence (a throw before that service's internal catch can never escape `handleError`; a fire-and-forget insert can be dropped by a serverless freeze), and returns before filing for a 404 or an unauthenticated caller (#153). `app.requestPipeline.db.test.ts › handleError auto-filing (issue 153)`.
- The cleanup cron needs `CRON_SECRET` on GET and POST: `Authorization: Bearer <secret>` or `x-cron-secret`, and with the variable unset every caller is refused with `401 {"error":"Unauthorized"}`. With the secret it answers `200` and the body is `success: true` plus `runRetention`'s seven keys. Pinned by `app.http.db.test.ts` › "answers 401 … without the secret, for GET and POST", "refuses every caller when CRON_SECRET is not configured", "runs the retention prunes with the secret and answers the legacy keys".
- Retention windows are app's: Anonymous Accounts inactive 90 d, read notifications 90 d, resolved phrases and closed bug reports 180 d, ad events 90 d, expired claim tokens at once. "Now" is `ctx.clock.now()`, read once per run; each prune's cutoff edge is strict (`<`), so a row exactly at the cutoff survives. Pinned by `app.retention.db.test.ts` › "deletes every row past its window and keeps the rest", "scans only Anonymous Accounts: a stale registered person stays".
- `/api/health` is public, always answers `200` with `{ok, db}` and `cache-control: no-store`, and the ping is bounded to 1 s: a rejecting or hanging database is `{ok:false, db:'down'}` — never a 500, never a stack, never a connection detail. Pinned by `app.http.db.test.ts` › "answers 200 {ok:false, db:\"down\"} — not 500, no internals — when the query rejects", "bounds a hanging database to one second".

None left: `server/utils/apiError.ts` (+ its test) had no importer (every route now answers through the kernel's error mapping, and faults are filed by this module's `handleError` through feedback), so it was deleted. The `web-push` ambient types moved here as `app.web-push.d.ts`.

## Depends on

- **May import:** anything. Prefer modules' public entries. Legacy imports are allowed here only, as transition bridges.
- **Owns tables:** none.
- **Called by:** `src/hooks.server.ts` (the ctx) and the two `+server.ts` routes; at runtime, Vercel cron (`vercel.json`, Mondays 04:00 UTC) calls the cleanup and uptime monitors call health.
