# marketing

**domain** — Public site: home, features, pricing display, roadmap/changelog, contact, SEO tags, Android/F-Droid page.

Domain words come from [CONTEXT.md](../../../../CONTEXT.md); use them exactly. Architecture rules: [docs/architecture/rules.md](../../../../docs/architecture/rules.md).

## Purpose

- Owns the signed-out public site: the content pages, their share metadata (one SEO table), and contact intake.
- Owns the `(marketing)` group's prerender/SSR flags and the `/android` view of the committed publish record `src/lib/fdroid/published.json`.
- Does not own: `/login`, `/signup`, `/forgot-password`, `/reset` behaviour (identity) — marketing only carries their SEO rows and links; `/pricing`'s amounts and discounts (billing's `checkoutService`/`analyticsService`) — marketing displays them; F-Droid artifacts (the release scripts build them, marketing never writes them).

## Public interface

The names below are the design the port builds on. The rules and the contract exist (S3, signatures as implemented); the entry files stay empty until the service and the handlers land (S5–S7). Each export earns its place by the deletion test. `marketing.contract.ts` (the contact bodies and responses) and `marketing.mail.rules.ts` (`CONTACT_RECIPIENT`, `contactSubject`, `isContactEmail`, `contactMessageHtml`) are imported by the service and the handlers inside the module and are not exported to other modules.

- `index.ts`:
  - `pageSeo(origin, pathname)` — the layout's single call: `{ title, description, canonical, meta }`, with `robots: noindex, follow` for the transactional paths. Delete it and the table lookup, the absolute-URL rule and the noindex rule move back into the layout — the drift the SEO test exists to stop.
  - `marketingPageOptions(adapter: string)` — `{ prerender, ssr }` for a `(marketing)` route: both on for `'static'`, both off for anything else. `CONTENT_PAGE_OPTIONS` is the always-on pair for `/changelog` and `/roadmap`. Delete them and the adapter rule plus its two overrides live in three route files that no test can import.
  - `MARKETING_NAV`, `CHANGELOG_ENTRIES`, `changelogNewestFirst(entries)`, `ROADMAP_SECTIONS` — the curated content: the fixed four nav links, the changelog (written newest-first; `changelogNewestFirst` is the stable sort the page uses), exactly three roadmap sections. Delete them and the data lives in a page nobody can check. Changelog dates format through kernel/time's `formatLongDate(date, 'UTC')` (`MMMM d, yyyy`, which is the legacy `Intl` output) — no local formatter.
  - `androidRelease(published: PublishedRepo)` — the `/android` view model (repo link, QR path, grouped fingerprint, APK size); the record is a parameter, the page load reads `src/lib/fdroid/published.json`. Delete it and the fingerprint/URL rules end up in the template.
  - `featureIcon(name: FeatureIconName)` — a closed icon vocabulary (`FEATURE_ICON_NAMES`); returns the tile colours and the SVG markup, the literals stay private.
- `index.server.ts`:
  - `contactEndpoint` — `POST /api/contact` as one use-case: rate limit (`contact` scope, 3/15 min), form parse, validation order, mail. A mail-provider failure is thrown as a **fault**, not an `AppError`, and the endpoint's `failMessage` carries the legacy 500 copy — so the wire matches and the kernel files the fault, exactly as the legacy `apiError` did. Delete it and the route reproduces the wire by hand.
  - `contactFormAction` — `/contact`'s action. A separate export, not a flag: its budget (5/10 min) and its 500 copy are fixed and differ from the `/api` one, and its 500 is a form failure (`fail`), not a filed fault.
  - `sendContactMessage` (the service behind the contact action) is the module's reference shape for a **public anonymous surface**: `(ctx, actor: Actor | null, input)`. Identity's and access's anonymous entry points reuse that shape rather than inventing a second anonymous writer.
  - `marketingLayoutLoad` — `origin`, `pathname`, `isLoggedIn`, `user`. The self-referencing origin is the rule; a hardcoded domain is the bug it prevents.
  - `androidPageLoad` — `{ release }` from the committed publish record.
  - `strayRootPostAction` — #276: a `POST /` answers 303 back to `/` and logs the sender hints instead of a 405 error page.
- `ui/index.ts`:
  - `FeatureCard`, `MomentCard`, `StrugglePanel`, `GalleryCard`, `TestimonialCard`, `PricingCard` — the cards the pages compose; each has a visual baseline, so they stay components rather than inline markup.
  - One section component per page (`HomeScreen` … `AndroidScreen`) so the route's `+page.svelte` stays a single render (R8).

## How to test

- Whole module: `npm run test:mod -- marketing` (add `--legacy` while legacy tests remain).
- Pure rules: `*.rules.test.ts`, plain tables of input → expected output, no setup.
- Database + services: `*.db.test.ts` using `rollbackTest` and `testCtx({ db })` (needs Postgres: `docker start familycalendar-db`).
- HTTP contract: [marketing.http.db.test.ts](marketing.http.db.test.ts) pins status + body of `POST /api/contact` (golden tests).
- The golden drives the legacy actions file directly, with `fetch` stubbed at the Resend boundary and a dummy `RESEND_API_KEY`, so it needs no network and no mail credentials. It asserts the HTTP contract only; the mail's copy and escaping are pinned by the service test, so a mailer port does not invalidate it. Each test that depends on a budget shares **one** `ctx` across its requests: after the port the limiter lives on `ctx`, and a fresh ctx per request would start every bucket empty (legacy ignores `ctx` and shares one module-scope map).
- UI: `ui/*.svelte.test.ts` render with props; state classes are tested without a DOM.
