# feedback

**domain** — Bug reports (user-filed and auto-filed faults), unmatched NLP phrases, the admin registers and their export.

Domain words come from [CONTEXT.md](../../../../CONTEXT.md); use them exactly. Architecture rules: [docs/architecture/rules.md](../../../../docs/architecture/rules.md).

## Purpose

- Owns: **Bug reports** (what a person filed from `/report-bug`, plus the ones the server files itself when something truly unexpected fails) and the two **admin registers** over them (`/admin/bugs`, `/admin/nlp`), with their plain-text "Export for agent" text.
- Owns: **Unmatched phrases** — the natural-language phrases a parser could not handle, deduplicated and counted so a parser rule can be written from the register.
- Does not own: deciding that a phrase is unmatched (the parser that called `/api/report-phrase` owns that rule), who may see the admin pages (`admin` screen), capturing a failure (`app`'s `Ctx.faults` port calls in here; the skip and throttle rules below it are ours), or any notification (nothing is sent).

## Public interface

Everything other modules and routes may use, grouped by entry file. One line each: `name` — what it does.

- `index.ts`:
  - `type BugArea`, `type UnmatchedSource`, `type FeedbackKind` (`'bug' | 'phrase'`) — the three closed vocabularies the services, the endpoints and the register switch on.
  - `type FeedbackBugRegister` / `type FeedbackPhraseRegister` — the two register shapes (`{ open, resolved }` with real `Date`s), declared in the contract and re-exported by `index.server.ts` for the admin screen's props.
  - `reportBugHref(currentPath)` — issue 257: the "report this page" link, carrying the current page as `from` (or `/report-bug` when there is no usable page).
  - `formatBugReportsExport(open, now, zone)` / `formatUnmatchedPhrasesExport(open, now, zone)` — the agent-ready text; lives here because the API and the page must produce byte-identical text, so `now` and the zone are parameters (both callers pass `ctx.clock.now()` and `'UTC'`).
  - `createFeedbackApi(client?)` — the browser client for `POST /api/report-phrase`, the two register reads and the two resolves; returns `ApiResult`, never throws.
  - `FeedbackBugRegisterState` / `FeedbackPhraseRegisterState` — one admin register's client state: `open`, `resolved`, `pendingId`, `exportText` (a getter over the open rows, issue 262), `today`, and `resolve(id)` with the optimistic move, rollback and toast. Constructor `(api, toasts, initial, now, zone)`.
  - `ReportBugState` — the `/report-bug` form's client state: `from` (kept across the post-submit reload, issue 257), `rememberFrom`, `submitting` / `startSubmit` / `finishSubmit` (issue 258).
  - `type FeedbackFormEnhancer` — the `$app/forms` `enhance` shape a component takes as a prop, declared here so `ui/` stays free of `$app/*`.
- `index.server.ts`:
  - `fileBugReport(ctx, actor, input)` — validate, trim/cap, store a user-filed report; the one write path for both `POST /api/bug-report` and the `/report-bug` action.
  - `fileAutoBugReport(ctx, fault)` — the fault filer: skip 404/blank/abort, derive the area from the path, throttle one per failure key per 10 minutes, store. Hides the whole auto-filing policy behind one call.
  - `reportUnmatchedPhrase(ctx, actor, input)` — normalize + upsert on `(source, phrase)`; never fails the caller.
  - `listFeedback(ctx, actor, kind)` — one admin register as `{ open, resolved }`; the admin gate lives here, so the screen cannot forget it.
  - `resolveFeedback(ctx, actor, kind, id)` — close one row of either register; `kind` picks the 404 copy.
  - `openBugReportCount(ctx)` / `openUnmatchedPhraseCount(ctx)` — one badge leg each: open bug reports (no `resolvedAt`) and open unmatched phrases (`resolved = false`). Split so the `admin` screen can degrade each badge on its own; the `/api/admin` golden pins one failing leg leaving the other leg's real count standing.
  - `countOpenFeedback(ctx)` — `{ bugs, phrases }`, the two legs in one call. The admin layout (the caller) owns the degrade-to-zero guard: a failing count renders 0, as legacy `guard('admin-counts', 0, …)` did (`src/lib/server/services/adminData.ts:36-37`), so the badge never fails the page.
  - `pruneFeedbackOlderThan(ctx, cutoff)` — 180-day retention for both tables; called by the cleanup cron in `app`.
  - `submitBugReportEndpoint`, `reportUnmatchedPhraseEndpoint`, `listBugReportsEndpoint`, `listUnmatchedPhrasesEndpoint`, `resolveBugReportEndpoint`, `resolveUnmatchedPhraseEndpoint` — the six route handlers; one name per route keeps the routes wiring-only (R8) and the names unique (R11).
  - `reportBugPageLoad` / `submitBugReportAction` — the `/report-bug` page's load (302 to `/login` when signed out, resolves `from`) and its `fail(…)` action.
  - `type FeedbackBugRegister` / `type FeedbackPhraseRegister` — re-exported from the contract so the admin screen types its page data from the server entry it already imports.
- `ui/index.ts`:
  - `ReportBugForm` — the `/report-bug` page body: area select, description, hidden `from`, Back link, inline error, pending submit, success panel; props `areas`, `from`, `form`, `enhance`.
  - `FeedbackRegister` — one register body for either kind: open items (cards for bugs, tables per source for phrases), the collapsible Resolved list, `pendingId` and `onresolve(id)`.
  - `FeedbackExport` — the readonly export textarea with Copy and Download, `today` for the filename, and the two toasts (copied / select-and-copy) through the `toasts` prop.

Module-internal, exported from no entry file: `BUG_AREAS`, `isBugArea`, `isUnmatchedSource`, `bugAreaLabel`, `unmatchedSourceLabel`, `normalizePhrase`, `isPhraseOverCap`, `unmatchedPhraseUpsert`, `bugAreaOf`, `bugReportDraft`, `areaForPath`, `buildAutoBugReport`, `safeReportedPath`, `groupUnmatchedPhrases`, `markBugReportResolved`, `markUnmatchedPhraseResolved` and `BUG_AREA_LABEL` / `UNMATCHED_SOURCE_LABEL` in `feedback.rules.ts`; `matchedSummary` / `reporterName` in `feedback.export.rules.ts`. No other module or route calls them — the services, the exporters and the register components are their only callers — so they stay internal, each tested by the `*.test.ts` next to its stem (the label helpers through `feedback.rules.test.ts › register labels`, the list edits through `› markBugReportResolved` / `› markUnmatchedPhraseResolved`, the grouping through `› groupUnmatchedPhrases`).

Two label sets, two homes, on purpose: the plain `BUG_AREA_LABEL` set (`calendar: 'Calendar'`, `tasks: 'Tasks'`, …) serves the export text and the register chips, and lives in `feedback.rules.ts` because the export is wire; the `/report-bug` select uses its own friendlier labels (`calendar: 'Calendar / events'`, `account: 'Account / settings'`, `payments: 'Payments / subscription'`, `other: 'Something else'`), which live in `ui/ReportBugForm.svelte` because they are only ever read by a person. Neither set may be used for the other purpose.

## How to test

- Whole module: `npm run test:mod -- feedback` (add `--legacy` while legacy tests remain).
- Pure rules: `*.rules.test.ts`, plain tables of input → expected output, no setup.
- Wire schemas: `feedback.contract.test.ts` — parse tables for every `/api` body and response (the 400 copy, absent-vs-null, ISO timestamps).
- Database + services: `*.db.test.ts` using `rollbackTest` and `testCtx({ db })` (needs Postgres: `docker start familycalendar-db`). `feedback.service.db.test.ts` pins the IO Invariants; `feedback.pages.http.db.test.ts` drives `/report-bug` through `invokeLoad` / `invokeAction`.
- HTTP contract: `feedback.http.db.test.ts` pins status + body of every endpoint (golden tests). Committed mode (`beforeEach(truncateAll)`); each test claims its own `x-real-ip`, and a test that counts a rate-limit budget shares one `ctx` across every request of the burst — the limiter lives on `ctx.limiter`, so a fresh `ctx` per request would start every bucket empty. `feedback.faults.http.test.ts` is the no-database twin for the write-failure path (the test ctx's db refuses access).
- Client state: `feedback.register.state.test.ts` / `feedback.report.state.test.ts` run in node (project `unit`) with a fake api and `memoryToasts()` — no DOM, no `vi.mock`.
- UI: `ui/*.svelte.test.ts` (project `ui`, jsdom) render with props and callbacks; no `vi.mock`, no `$app/*` — `enhance` is a prop. The visual/perf checks are the Playwright pair: `npm run visual:check -- feedback` and `npm run perf:check -- feedback`.
- Fixtures: `feedback.fixtures.server.ts` (`seedBugReport`, `seedUnmatchedPhrase`).
