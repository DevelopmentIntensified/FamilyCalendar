# parsing

**domain** — Natural-language grammars: event quick-add, task quick-add (shared parse vectors with Android), the date vocabulary and the claim book.

Domain words come from [CONTEXT.md](../../../../CONTEXT.md); use them exactly. Architecture rules: [docs/architecture/rules.md](../../../../docs/architecture/rules.md).

## Purpose

- Owns: the phrase grammars behind quick-add — one event parse (date, time, recurrence, place, attendants, calendar, title), the multi-event fan-out, and the Task quick-add grammar (priority, due date, cadence, `#tags`, roster scoping).
- Owns: the one date vocabulary (month/weekday/ordinal/unit tokens, typo-tolerant weekday matching), the one rollover + cadence resolution, and the claim book that keeps two grammar families off one span.
- Does not own: persistence — no tables, no repo. The quick-add result is a prefill hint the caller confirms, never a write.
- Does not own: the bills grammar (bill cues, merchant keywords) — deleted by owner ruling Q-002 before this port, with the bills module. No components: the event/task editors and previews live in their own modules.

## Public interface

Everything other modules and routes may use, grouped by entry file. One line each: `name` — what it does.

- `index.ts`:
  - `parseTaskQuickAdd(input: string, options: TaskQuickAddOptions)` — the Task quick-add grammar: priority, due date, cadence, `#public`/`#private`, `@family`, `@member`/`for Name`, `#tags`, and the rebuilt title. `TaskQuickAddOptions` is `{ now: Date; zone: string; members?: TaskQuickAddMember[] }`: `now` is required because every relative date resolves against it (R5), `zone` is REQUIRED because every due date lands at 23:59 in that zone, never the host's, and the roster makes assignee matching scoped. The result carries `priorityStated` so a caller can tell "the phrase said high" from "high is the default", plus `hasInfo`/`summaryLabel` so a preview never re-derives "is there anything to show".
  - `findTaskAssignee(input, members)` — the roster-scoped assignee match (`TaskAssigneeMatch | null`), the same rule the parse uses. `normalizeQuickAddTags(matches)` — lowercase, de-duplicate, sort.
  - `TaskQuickAddResult`, `TaskQuickAddMember`, `TaskQuickAddOptions`, `QuickAddPriority` (the parsed `'high' | 'normal' | 'low'`; tasks reuses this one type and maps it to its tone — one concept, R11), the vocabulary values (`MONTH_*`, `WEEKDAY_*`, `DAY_ALT`, `DAY_MAP`/`dayNumber`, `ORDINAL_*`, `DAYPART_TIMES`, `TOD_TIMES`, `RECURRENCE_UNITS`, `extractDayTokens`/`DayToken`, `fuzzyDayToken`, `normalizeDayToken`, `normalizeMeridiem`/`normalizeTime`/`applyPeriod`, `escapeRegExp`) and the cadence values (`Cadence`, `CadenceUnit`, `CadenceMatch`, `cadenceUnit`, `cadenceToValue`, `valueToCadence`, `cadenceFrequency`, `matchCadence`, `CADENCE_FREQUENCIES`) — the result and input types callers render. A parsed cadence's storage word is kernel/time's `RecurrenceFrequency`, not a parsing type.
- `index.server.ts`:
  - `parseEventQuickAdd(input: string, options: EventQuickAddOptions)` — parses one quick-add phrase into `{ parsed, confidence, hasInfo, summaryLabel }`; hides the whole rule chain (claim book, date/time/recurrence/place/attendant grammars, title rebuild). `EventQuickAddOptions` is `{ now: Date; zone: string }`: `now` is required (R5), and `zone` is REQUIRED — it decides which calendar day "tomorrow" is and the 23:59 landing of every relative date.
  - `parseEventQuickAddList(input: string, options: EventQuickAddOptions)` — the same parse per segment for phrases naming several events ("dinner Friday and movie Saturday"); one entry when the phrase is a single event.
  - `ParsedEvent`, `EventQuickAddResult`, `EventQuickAddOptions` — the event result and input types callers render.
  - `parseEventRequest(ctx, actor, { input, useCloud, clientKey })` — the `POST /api/parse-event` use-case: the local parse first, the stored zone (identity) as the required rule zone, the tier and free 20/5 min window (billing), the multi-event shortcut before the cloud path, the monthly cap refused as an `AppError` 429 before any vendor call, the `ctx.ai` completion, the usage record even on an empty answer, and the 200 `regex-fallback` wire (with a fault report) when a later step throws. `ParseEventServiceInput` is the request type; `clientKey` is `clientKeyOf(request, 'parse-event')`, so the service takes no `Request`.
  - `submitParseEventEndpoint` — `POST /api/parse-event`: the contract's body and one 400 copy, anonymous callers answered by the local parser only, the service's 429 for the monthly cap, and the `regex` / `cloud` / `regex-fallback` / `regex-list` wire shapes.
- `ui/index.ts`: nothing — parsing has no user-visible surface of its own.

Cost line and the import rule: the event parser pulls in `compromise` (~352 KB minified), so it is exported from `index.server.ts` only and never from the isomorphic `index.ts`; a client bundle that imports `index.ts` must not pay for it. Consequently the task and vocabulary/date rule files never import the event rules (and the event rules never import task rules): a rule file imports vocabulary, the cadence rules and kernel only, so `parsing.task.rules.ts` and `parsing.vocabulary.rules.ts` stay client-safe and only the event files reach `compromise`.

Types that never cross the wire — `TaskQuickAddResult`, `TaskQuickAddMember`, `TaskQuickAddOptions`, `EventQuickAddOptions`, `QuickAddPriority`, `ParseEventServiceInput` — live in their rules/service files (`parsing.task.rules.ts`, `parsing.event.rules.ts`, `parsing.service.server.ts`), not in `parsing.contract.ts`: the contract file is only the zod wire shapes for `/api`.

Why this shape (deletion test): deleting either `parse…QuickAdd` would move its body, unchanged, into every caller — the route, the event editor, the task preview and the e2e suites all need the same chain, so it stays behind one function. `hasInfo`/`summaryLabel` ride on the result (architecture review 2026-11-10 #4) so previews never re-derive "is there anything to show" with an 8-way OR. Internally one vocabulary file feeds every grammar (#1/#5): no second month map, weekday order or ordinal table.

## How to test

- HTTP contract: `parsing.http.db.test.ts` pins status + the WHOLE body of `POST /api/parse-event` (`toEqual`; only clock-derived dates are computed from `DateTime.now()` in the caller's zone — never a weekday-only check). Golden tests; committed mode, needs Postgres.
- Whole module: `npm run test:mod -- parsing`. The legacy phrase suites are gone; only `dateVocab.test.ts` and `dateResolution.test.ts` remain, beside the three legacy sources that tasks and bulkAi still import (S8 note in the sheet).
- Pure rules: `*.rules.test.ts`, plain tables of input → expected output, no setup — the phrase tables are the test-first surface (AGENTS.md NLP rule).
- Database + services: `*.db.test.ts` using `rollbackTest` and `testCtx({ db })` (needs Postgres: `docker start familycalendar-db`).
- UI: none (no components).
- Fixtures: none — the module owns no tables; kernel `seedUser` + billing's fixtures cover the AI-cap cases.

## Invariants

Behaviour that must not change, each with the test that pins it (`file › test title`):

- One rollover rule for event, task and (former) bill dates: an explicit year wins even when past; otherwise the current year rolls +1 only when the month-day sits strictly before today — today stays today; a clamped day never rolls; an impossible month/day returns null — `src/lib/utils/dateResolution.ts:73-98` · pinned by `parsing.dates.rules.test.ts` (carries `dateResolution.test.ts › "keeps TODAY as today…"`, `"clamps the day to a short month…"`).
- `daysInMonth` is pure proleptic-Gregorian arithmetic, never a `Date` probe, so "Feb 29" in a common year is 28 and cannot roll into March — `src/lib/utils/dateResolution.ts:34-55` · `parsing.dates.rules.test.ts › "holds the rule across every day of a leap and a non-leap year"`.
- A bare weekday is always the next occurrence, 1..7 days out; today itself is 7, never 0 — `src/lib/utils/dateResolution.ts:100-104`, `naturalLanguageService.ts:65-75` · `parsing.dates.rules.test.ts › "never returns 0"`.
- Cadence wire vocabulary is `daily|weekly|biweekly|monthly|yearly|every_N_units`; `biweekly` is every-2-weeks, `every_2_days`/`every_2_months` never collapse into it; `valueToCadence` still reads legacy `every_2_weeks`; `cadenceFrequency` collapses every-N to the four storage words — `src/lib/utils/dateResolution.ts:157-205` · `parsing.dates.rules.test.ts › "every 2 weeks is weekly x 2, whichever parser and whichever value word"`.
- The shared cadence phrase table is ordered longest-first and first match wins (`every other <unit>`, `every N <unit>`, quarterly, biannually, `daily|nightly`, `weekly`, `monthly`, `yearly|annually`); the optional `repeat(s)` prefix is inside the matched span so it is stripped from titles — `src/lib/utils/dateResolution.ts:213-282` · `parsing.dates.rules.test.ts › "matchCadence — the shared cadence phrase table"` (36 phrases, 9 non-cadences such as "once a month", "every saturday").
- `dateVocab` is the one token address: months incl. `jun`/`jul` and longest-first `MONTH_ALT`, ordinal words in hyphen/spaced/fused forms, full + short weekdays, daypart and time-of-day anchors, recurrence unit words — `src/lib/utils/dateVocab.ts:74,94,157-183,242-262` · `parsing.vocabulary.rules.test.ts › "MONTH_ALT is longest-first (september before sep and sept)"` (29 legacy tests: 18 `it()` + an 11-row `it.each`). - Weekday typos resolve fuzzily: words under 4 chars never match, month names never match, exact names win before the edit-distance scan, adjacent transposition counts as one typo, budget 1 below 7 chars and 2 from 7 — `src/lib/utils/dateVocab.ts:218-241` · `parsing.vocabulary.rules.test.ts › "does not invent weekdays from short words (\"we sat by the sun\")"`.

- URLs are captured whole, removed from every date/title/time scan (`nonUrlText`), ride into `description`, and can never be cut by the 50-char title window — `naturalLanguageService.ts:483-487,2019-2022` · `parsing.event.rules.test.ts › "URL fidelity (issue 025)"`, `parsing.event-times.rules.test.ts › "a clock inside a URL never sets a start time (Q-010 B)"`.

## Notes

- Titles keep the trailing space a stripped span leaves behind whenever that span was consumed BEFORE the 50-char window was taken (a recurrence phrase, a URL, a terminal "with"-list, an "until" date): the window then has nothing left to strip, so the refinement never runs. The frozen golden pins it — `parsing.http.db.test.ts` › `"payday every other week" … the title keeps its trailing space` (`'payday '`), `"medication every 3 days"` (`'medication '`), `"coffee with John"` (`'coffee '`) — and `parsing.event-recurrence.rules.test.ts` › "the recurrence phrase never leaks into the title" restates it for `'yoga '`, `'chores '`, `'hoa dues '`, `'gym '`. Pinning a trimmed title here would contradict the golden: do not add a `trim()` to `buildEventTitle`.
- Attachment: the attendants group rule (`including X`, `the whole X`) is NOT global.
