# parsing

**domain** — Natural-language grammars: event quick-add, task quick-add (shared parse vectors with Android), the date vocabulary and the claim book.

Domain words come from [CONTEXT.md](../../../../CONTEXT.md); use them exactly. Architecture rules: [docs/architecture/rules.md](../../../../docs/architecture/rules.md).

## Purpose

- Owns: the phrase grammars behind quick-add — one event parse (date, time, recurrence, place, attendants, calendar, title), the multi-event fan-out, and the Task quick-add grammar (priority, due date, cadence, `#tags`, roster scoping).
- Owns: the one date vocabulary (month/weekday/ordinal/unit tokens, typo-tolerant weekday matching), the one rollover + cadence resolution, and the claim book that keeps two grammar families off one span.
- Does not own: persistence — no tables, no repo. The quick-add result is a prefill hint the caller confirms, never a write.
- Does not own: the bills grammar (`parseBillQuickAdd`, bill cues, merchant keywords) — deleted by owner ruling Q-002 before this port, with the bills module. No components: the event/task editors and previews live in their own modules.

## Public interface

Everything other modules and routes may use, grouped by entry file. One line each: `name` — what it does.

- `index.ts`:
  - `parseEventQuickAdd(input: string, options: EventQuickAddOptions)` — parses one quick-add phrase into `{ parsed, confidence, hasInfo, summaryLabel }`; hides the whole rule chain (claim book, date/time/recurrence/place/attendant grammars, title rebuild). `EventQuickAddOptions` is `{ now: Date; zone?: string }`: `now` is required because every relative date is resolved against it (R5), and `zone` decides which calendar day "tomorrow" is.
  - `parseEventQuickAddList(input: string, options: EventQuickAddOptions)` — the same parse per segment for phrases naming several events ("dinner Friday and movie Saturday"); one entry when the phrase is a single event.
  - `parseTaskQuickAdd(input: string, options: TaskQuickAddOptions)` — the Task quick-add grammar: priority, due date, cadence, `#public`/`#private`, `@family`, `@member`/`for Name`, `#tags`, and the rebuilt title. `TaskQuickAddOptions` is `{ now: Date; members?: TaskQuickAddMember[] }` — the roster makes assignee matching scoped, and `now` drives every due date.
  - `ParsedEvent`, `EventQuickAddResult`, `EventQuickAddOptions`, `TaskQuickAddResult`, `TaskQuickAddMember`, `TaskQuickAddOptions`, `QuickAddPriority` (the parsed `'high' | 'normal' | 'low'`, from which tasks derives its tone), `CadenceFrequency` — the result and input types callers render.
- `index.server.ts`:
  - `submitParseEventEndpoint` — `POST /api/parse-event`: validation, anonymous-regex-only, plan-gated cloud path, AI spend cap, wire shapes.
- `ui/index.ts`: nothing — parsing has no user-visible surface of its own.

Why this shape (deletion test): deleting either `parse…QuickAdd` would move its body, unchanged, into every caller — the route, the event editor, the task preview and the e2e suites all need the same chain, so it stays behind one function. `hasInfo`/`summaryLabel` ride on the result (architecture review 2026-11-10 #4) so previews never re-derive "is there anything to show" with an 8-way OR. Internally one vocabulary file feeds every grammar (#1/#5): no second month map, weekday order or ordinal table.

## How to test

- HTTP contract: `parsing.http.db.test.ts` pins status + body of `POST /api/parse-event` (golden tests; committed mode, needs Postgres).
- Whole module: `npm run test:mod -- parsing` (add `--legacy` while the legacy phrase suites remain).
- Pure rules: `*.rules.test.ts`, plain tables of input → expected output, no setup — the phrase tables are the test-first surface (AGENTS.md NLP rule).
- Database + services: `*.db.test.ts` using `rollbackTest` and `testCtx({ db })` (needs Postgres: `docker start familycalendar-db`).
- UI: none (no components).
- Fixtures: none — the module owns no tables; kernel `seedUser` + billing's fixtures cover the AI-cap cases.

## Invariants

Behaviour that must not change, each with the test that pins it (`file › test title`):

- One rollover rule for event, task and (former) bill dates: an explicit year wins even when past; otherwise the current year rolls +1 only when the month-day sits strictly before today — today stays today; a clamped day never rolls; an impossible month/day returns null — `src/lib/utils/dateResolution.ts:73-98` · pinned by `parsing.dates.rules.test.ts` (carries `dateResolution.test.ts › "keeps TODAY as today…"`, `"clamps the day to a short month…"`).
- `daysInMonth` is pure proleptic-Gregorian arithmetic, never a `Date` probe, so "Feb 29" in a common year is 28 and cannot roll into March — `src/lib/utils/dateResolution.ts:34-55` · `parsing.dates.rules.test.ts › "holds the rule across every day of a leap and a non-leap year"`.
- A bare weekday is always the next occurrence, 1..7 days out; today itself is 7, never 0 — `src/lib/utils/dateResolution.ts:100-104`, `naturalLanguageService.ts:65-75` · `parsing.dates.rules.test.ts › "never returns 0"`.
- Cadence wire vocabulary is `daily|weekly|biweekly|monthly|yearly|every_N_units`; `biweekly` is every-2-weeks, `every_2_days`/`every_2_months` never collapse into it; `valueToCadence` still reads legacy `every_2_weeks`; `cadenceFrequency` collapses every-N to the four storage words — `src/lib/utils/dateResolution.ts:157-205` · `parsing.dates.rules.test.ts › "every 2 weeks is weekly x 2, whichever parser and whichever value word"`.
- The shared cadence phrase table is ordered longest-first and first match wins (`every other <unit>`, `every N <unit>`, quarterly, biannually, `daily|nightly`, `weekly`, `monthly`, `yearly|annually`); the optional `repeat(s)` prefix is inside the matched span so it is stripped from titles — `src/lib/utils/dateResolution.ts:213-282` · `parsing.dates.rules.test.ts › "matchCadence — the shared cadence phrase table"` (36 phrases, 9 non-cadences such as "once a month", "every saturday").
- `dateVocab` is the one token address: months incl. `jun`/`jul` and longest-first `MONTH_ALT`, ordinal words in hyphen/spaced/fused forms, full + short weekdays, daypart and time-of-day anchors, recurrence unit words — `src/lib/utils/dateVocab.ts:74,94,157-183,242-262` · `parsing.vocabulary.rules.test.ts › "MONTH_ALT is longest-first (september before sep and sept)"` (29 legacy tests: 18 `it()` + an 11-row `it.each`). No other map may reappear (review #1/#5).
- Weekday typos resolve fuzzily: words under 4 chars never match, month names never match, exact names win before the edit-distance scan, adjacent transposition counts as one typo, budget 1 below 7 chars and 2 from 7 — `src/lib/utils/dateVocab.ts:218-241` · `parsing.vocabulary.rules.test.ts › "does not invent weekdays from short words (\"we sat by the sun\")"`.
- `dateParsing` is only a thin re-export layer over `dateVocab` (MONTH_ALT, 1-based MONTH_MAP, full-weekday DAY_MAP, `normalizeMeridiem` stripping periods so "p.m."/"a. m." become `pm`/`am`) — `src/lib/server/utils/dateParsing.ts:8-60` · `parsing.vocabulary.rules.test.ts › "Perioded meridiem (\"8:00 p.m.\") + activity-then-place suffix (#207)"`.
- URLs are captured whole, removed from every date/title scan, ride into `description`, and can never be cut by the 50-char title window — `naturalLanguageService.ts:483-487,2019-2022` · `parsing.event.rules.test.ts › "URL fidelity (issue 025)"`.
- An early `until <date>` capture is blanked at the same character length so it can never be stolen as the event date, and only becomes `recurringUntil` when a frequency was found — `naturalLanguageService.ts:488-503,1165-1174` · `parsing.event.rules.test.ts › "parses \"yoga every Monday until Dec 15\" without stealing the date"`.
- Claim book: each grammar family claims exactly the span it consumed; overlapping claims are dropped; `maskClaims` blanks claimed ranges at the same offsets (newlines preserved) and feeds the weekday scan, bare-weekday fallback, invite list, calendar targeting and the "at my"/"on <address>" reads — `naturalLanguageService.ts:505-526,1117,1181,1700-1712,1740,1753,1824` · `parsing.claims.rules.test.ts` (carries `parserClaimGuards.test.ts`, 12 cases) › "a weekly scan does not re-claim the weekday of a date rule".
- Date chain is first-match-wins: `this <weekday>`, `next <weekday>` (+1 week), today, tomorrow, `in N days|weeks|months`, `in N min|hrs` (also sets startTime), weekend → upcoming Saturday (Saturday today → +7), `next <month>` → 1st of that month next year, `returning [by] <weekday> [daypart]`, month-day, day-first, ISO, ordinal digit-first, ordinal word, ordinal weekday, `MM/DD` — `naturalLanguageService.ts:543-771` · `parsing.event.rules.test.ts` (the legacy `Date Patterns`, `Additional Date Formats` and `Relative Date Offsets` suites).
- An ordinal weekday (`first…fifth|last <weekday> of <month|the month>`) that cannot exist resolves to no date; when in the past it advances a month ("the month") or a year (named month) — `naturalLanguageService.ts:77-104,725-760` · `parsing.event.rules.test.ts › "parses \"deadline last Friday of the month\" as a late-month Friday"`.
- The explicit-date sweep collects every named date with its span; continuations (`& 30`, `, 12`, `and 19`) borrow month/year from the nearest preceding date, and a following colon marks a time, never a day — `naturalLanguageService.ts:773-857` · `parsing.event.rules.test.ts › "parses \"book club sept 5, 12, and 19\" as three dates"`.

- All-day cues are `all day`, `all-day`, `whole day`, `birthday`; an all-day event with no start time defaults to 09:00–17:00 — `naturalLanguageService.ts:1035-1039,2027-2030` · `parsing.event.rules.test.ts › "parses \"all day\" as allDay"`.
