# parsing

**domain** — Natural-language grammars: event quick-add, task quick-add (shared parse vectors with Android), the date vocabulary and the claim book.

Domain words come from [CONTEXT.md](../../../../CONTEXT.md); use them exactly. Architecture rules: [docs/architecture/rules.md](../../../../docs/architecture/rules.md).

## Purpose

- Owns: the phrase grammars behind quick-add — one event parse (date, time, recurrence, place, attendants, calendar, title), the multi-event fan-out, and the Task quick-add grammar (priority, due date, cadence, `#tags`, roster scoping).
- Owns: the one date vocabulary (month/weekday/ordinal/unit tokens, typo-tolerant weekday matching), the one rollover + cadence resolution, and the claim book that keeps two grammar families off one span.
- Does not own: persistence — no tables, no repo. The quick-add result is a prefill hint the caller confirms, never a write.
- Does not own: the bills grammar (`parseBillQuickAdd`, bill cues, merchant keywords) — deleted by owner ruling Q-002 before this port, with the bills module. No components: the event/task editors and previews live in their own modules.

## Public interface

Everything other modules and routes may use, grouped by entry file. One line each: `name` — what it does.

- `index.ts`:
  - `parseTaskQuickAdd(input: string, options: TaskQuickAddOptions)` — the Task quick-add grammar: priority, due date, cadence, `#public`/`#private`, `@family`, `@member`/`for Name`, `#tags`, and the rebuilt title. `TaskQuickAddOptions` is `{ now: Date; zone: string; members?: TaskQuickAddMember[] }`: `now` is required because every relative date resolves against it (R5), `zone` is REQUIRED because every due date lands at 23:59 in that zone, never the host's, and the roster makes assignee matching scoped. The result carries `priorityStated` so a caller can tell "the phrase said high" from "high is the default" without re-running the priority regex.
  - `TaskQuickAddResult`, `TaskQuickAddMember`, `TaskQuickAddOptions`, `QuickAddPriority` (the parsed `'high' | 'normal' | 'low'`; tasks reuses this one type and maps it to its tone — one concept, R11), the vocabulary/date rules' public values (a parsed cadence's storage word is kernel/time's `RecurrenceFrequency`, not a parsing type) — the result and input types callers render.
- `index.server.ts`:
  - `parseEventQuickAdd(input: string, options: EventQuickAddOptions)` — parses one quick-add phrase into `{ parsed, confidence, hasInfo, summaryLabel }`; hides the whole rule chain (claim book, date/time/recurrence/place/attendant grammars, title rebuild). `EventQuickAddOptions` is `{ now: Date; zone: string }`: `now` is required (R5), and `zone` is REQUIRED — it decides which calendar day "tomorrow" is and the 23:59 landing of every relative date.
  - `parseEventQuickAddList(input: string, options: EventQuickAddOptions)` — the same parse per segment for phrases naming several events ("dinner Friday and movie Saturday"); one entry when the phrase is a single event.
  - `ParsedEvent`, `EventQuickAddResult`, `EventQuickAddOptions` — the event result and input types callers render.
  - `submitParseEventEndpoint` — `POST /api/parse-event`: validation, anonymous-regex-only, plan-gated cloud path, AI spend cap, wire shapes.
- `ui/index.ts`: nothing — parsing has no user-visible surface of its own.

Cost line and the import rule: the event parser pulls in `compromise` (~352 KB minified), so it is exported from `index.server.ts` only and never from the isomorphic `index.ts`; a client bundle that imports `index.ts` must not pay for it. Consequently the task and vocabulary/date rule files never import the event rules (and the event rules never import task rules): a rule file imports vocabulary + kernel only, so `parsing.task.rules.ts` and `parsing.vocabulary.rules.ts` stay client-safe.

Types that never cross the wire — `TaskQuickAddResult`, `TaskQuickAddMember`, `TaskQuickAddOptions`, `EventQuickAddOptions`, `QuickAddPriority` — live in their rules files (`parsing.task.rules.ts`, `parsing.event.rules.ts`), not in `parsing.contract.ts`: the contract file is only the zod wire shapes for `/api`.

Why this shape (deletion test): deleting either `parse…QuickAdd` would move its body, unchanged, into every caller — the route, the event editor, the task preview and the e2e suites all need the same chain, so it stays behind one function. `hasInfo`/`summaryLabel` ride on the result (architecture review 2026-11-10 #4) so previews never re-derive "is there anything to show" with an 8-way OR. Internally one vocabulary file feeds every grammar (#1/#5): no second month map, weekday order or ordinal table.

## How to test

- HTTP contract: `parsing.http.db.test.ts` pins status + the WHOLE body of `POST /api/parse-event` (`toEqual`; only clock-derived dates are computed from `DateTime.now()` in the caller's zone — never a weekday-only check). Golden tests; committed mode, needs Postgres.
- Whole module: `npm run test:mod -- parsing` (add `--legacy` while the legacy phrase suites remain).
- Pure rules: `*.rules.test.ts`, plain tables of input → expected output, no setup — the phrase tables are the test-first surface (AGENTS.md NLP rule).
- Database + services: `*.db.test.ts` using `rollbackTest` and `testCtx({ db })` (needs Postgres: `docker start familycalendar-db`).
- UI: none (no components).
- Fixtures: none — the module owns no tables; kernel `seedUser` + billing's fixtures cover the AI-cap cases.
