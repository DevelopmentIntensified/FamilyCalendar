# tasks

**domain** — Tasks: visibility, priority, assignment handoff, Recurring Task cursor, tags, categories, completions, stats/streaks, archive, TaskFocus focus time + phone sessions, task UI.

Domain words come from [CONTEXT.md](../../../../CONTEXT.md); use them exactly. Architecture rules: [docs/architecture/rules.md](../../../../docs/architecture/rules.md).

## Purpose

- Owns the **Task**: creation, edits, deletion/archiving, the **Task Visibility** rule, the assignment handoff (**Requested / To Accept**), Task Priority, tags, per-user categories, and **completion history**.
- Owns the **Recurring Task** cursor (one live occurrence, skip and undo), the overdue pin that runs before reads, and the completion counts stats and the weekly streak are built from.
- Owns TaskFocus: the desktop focus fields (`focusMinutes`, `focusStartedAt`), the phone focus sessions and their absorb ack, and the per-user device command FIFO.
- Owns the task UI: the `/calendar/tasks` page state and components, plus the Task pieces other screens embed (the event checklist).
- Does not own: Events and calendars (calendar — a Task may attach to an Event and is filtered by its calendar), the Alert feed storage and push fan-out (alerts — tasks only asks it to notify), Family membership and the roster (family), quick-add grammar and date vocabulary (parsing), Task rendering inside the Day Dashboard cards (dayDashboard composes this module), plan retention for the archive page (billing/calendar).

## Public interface

Everything other modules and routes may use, grouped by entry file. One line each: `name` — what it does. Every service takes its inputs in ONE object (`ctx` first, the input object last); the actor and ids ride inside it.

- `index.ts`:
  - `TaskWire`, `TaskWithTagsWire`, `TaskCategoryWire`, `FocusCommandWire`, `FocusSessionWire` — the `/api` shapes (absent-vs-null documented per field).
  - `TaskCreateBody`, `TaskUpdateBody`, `TaskCategoryNameBody`, `FocusCommandBody`, `FocusSessionStartBody`, `FocusSessionEndBody` — zod schemas for every request body, with the legacy error wording.
  - `normalizeTags`, `normalizeTaskVisibility` — the tag and visibility rules.
  - `normalizeTaskPriority` — returns parsing's `QuickAddPriority` (the quick-add result's own type; the tone map stays with the pill in `kernel/ui`), so a Task's priority and a parsed title's priority are ONE concept.
  - the recurrence frequency has NO home here: it is calendar's `RecurrenceFrequency` (`scheduleStep`'s closed set), which parsing re-exports as `CadenceFrequency` for quick add — a Task's `recurrenceFrequency`, an Event's and a parsed cadence are one vocabulary.
  - `nextCursorDue` — the Recurring Task cursor advance (today + n×interval strictly past the current due), used by the completion, skip and undo. The pin (`needsOverduePin`, `pinnedDueFor`) stays inside the module: it is a read-side service concern, not an interface other modules call.
  - `canMutateTask`, `nextAssignmentPatch` — the two rules that decide what a caller may do to a Task and how an assignment moves (pure; membership arrives as a flag).
  - `computeWeeklyStreak` — the one streak definition, shared with the Day Dashboard (`isoWeekKey` and the cursor's day-start helper live in `kernel/time`, task K-06, with every other date key).
  - `rankTasks` — mine-first → priority → overdue → due-today → next-due → title (Top-3 Priorities and the Family Task Board order through it).
  - `createTasksApi` — typed browser client for this module's endpoints (kernel api client); no UI state.
- `index.server.ts`:
  - `listTasks(ctx, input)` — `{ eventId?, actor }`: one read for both list shapes. ## How to test

- Whole module: `npm run test:mod -- tasks` (add `--legacy` while legacy tests remain).
- Pure rules: `*.rules.test.ts`, plain tables of input → expected output, no setup.
- Database + services: `*.db.test.ts` using `rollbackTest` and `testCtx({ db })` (needs Postgres: `docker start familycalendar-db`).
- HTTP contract: `tasks.http.db.test.ts`, `tasks.update.http.db.test.ts`, `tasks.focus.http.db.test.ts` pin status + body of every endpoint (golden tests, committed mode). They run against the legacy handlers today and must not change at S6.
- Exact timestamp strings: `tasks.dueDate` / `completedAt` / `archivedAt` and `events.start` are `timestamptz` columns in drizzle `mode:'string'`, so the body carries the POSTGRES render (`2026-02-01 10:00:00+00`), not an ISO string; only `createdAt`/`focusStartedAt`/phone-session instants are `mode:'date'` and serialize as ISO. The `+00` suffix depends on the Postgres session `TimeZone`, which docker and production both pin to UTC — a session on another zone renders `+14` and every golden fails, which is the intended tripwire.
- UI: `ui/*.svelte.test.ts` render with props; the page state class is tested in `tasks.page.state.test.ts` with a fake api and no DOM.
- Fixtures: `tasks.fixtures.server.ts` (row builders for this module's tests; the only place a test creates task, tag, completion, category, command, session or user-zone rows).
