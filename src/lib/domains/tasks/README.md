# tasks

**domain** — Tasks: visibility, priority, assignment handoff, Recurring Task cursor, tags, categories, completions, stats/streaks, archive, TaskFocus focus time + phone sessions, task UI.

Domain words come from [CONTEXT.md](../../../../CONTEXT.md); use them exactly. Architecture rules: [docs/architecture/rules.md](../../../../docs/architecture/rules.md).

## Purpose

- Owns the **Task**: creation, edits, deletion/archiving, the **Task Visibility** rule, the assignment handoff (**Requested / To Accept**), Task Priority, tags, per-user categories, and **completion history**.
- Owns the **Recurring Task** cursor (one live occurrence, skip and undo), the overdue pin that runs before reads, and the completion counts stats and the weekly streak are built from.
- Owns TaskFocus: the desktop focus fields (`focusMinutes`, `focusStartedAt`), the phone focus sessions and their absorb ack, and the per-user device command FIFO.
- Owns the task UI: the `/calendar/tasks` page state and components, plus the Task pieces other screens embed (the event checklist).
- Does not own: Events and calendars (calendar — a Task may attach to an Event and is filtered by its calendar), the Alert feed storage and push fan-out (alerts — tasks only asks it to notify), Family membership and the roster (family), quick-add grammar and date vocabulary (parsing), Task rendering inside the Day Dashboard cards (dayDashboard composes this module), plan retention for the archive page (billing/calendar).

## Public interface

Everything other modules and routes may use, grouped by entry file. One line each: `name` — what it does.

- `index.ts`:

  - `nextCursorDue`, `needsOverduePin`, `pinnedDueFor` — the Recurring Task cursor math and the overdue pin ("now" and the user's zone are parameters).

- `index.server.ts`:
  - `listTasks(ctx, actor, { eventId? })` — one read for both list shapes: pins stale cursors first, attaches tags, `eventCalendarId` and the phone-focus overlay, hides other members' private event Tasks.

  - `listFocusCommands`, `issueFocusCommand`, `ackFocusCommand` — the per-user device command FIFO.

  - `getTaskStats`, `listCompletionInstants`, `getStatsPage` — the counting path (shared with the dashboard) and the `/api/stats` body.

- `ui/index.ts`:
  - `TaskList`, `TaskRow`, `TaskSections`, `TaskToolbar` — the `/calendar/tasks` lists (chips, jump bar, tail states) and their rows.

Deletion test (why each export stays): `listTasks` is the single read behind seven legacy readers (user list, event list, my Tasks, pending, requested, public tab, family board) — deleting it would paste visibility, the cursor pin, tag attachment and the phone overlay into every caller. `updateTask` swallows the 353-line route dispatch (undo, skip, toggle, five patch groups) so the dispatch order cannot drift from the rules. `canMutateTask`/`nextAssignmentPatch` are the one home for the rules that three routes and the UI repeat today. `nextCursorDue`/`needsOverduePin` are the pure cursor policy shared by the reader pin, the completion, skip and undo. `summarizePhoneFocus` keeps the floor-of-the-sum overlay out of the list query. `computeWeeklyStreak` is reused by the stats page and the Day Dashboard. `rankTasks` replaces the three floating sort helpers (`taskSort`, `dashboard` selectors, `taskUrgency`). The endpoint handlers exist so every route file stays wiring-only (R8).

## How to test

- Whole module: `npm run test:mod -- tasks` (add `--legacy` while legacy tests remain).

- Database + services: `*.db.test.ts` using `rollbackTest` and `testCtx({ db })` (needs Postgres: `docker start familycalendar-db`).
- HTTP contract: `tasks.http.db.test.ts`, `tasks.update.http.db.test.ts`, `tasks.focus.http.db.test.ts` pin status + body of every endpoint (golden tests, committed mode). They run against the legacy handlers today and must not change at S6.
- UI: `ui/*.svelte.test.ts` render with props; the page state class is tested in `tasks.page.state.test.ts` with a fake api and no DOM.
- Fixtures: `tasks.fixtures.server.ts` (row builders for this module's tests).
